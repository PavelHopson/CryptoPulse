# CryptoPulse Research Lab — коммерческий план

Документ описывает путь от текущей client-only лаборатории к продукту для обучения,
исследования рынка и paper trading. Он не включает реальные сделки, копи-трейдинг
или обещания доходности.

## Этапы

### 1. Честное позиционирование

- Название продукта: CryptoPulse Research Lab.
- На каждом экране виден источник данных: `LIVE`, `CACHED`, `MOCK`, `RETRY` или `UNAVAILABLE`.
- Mock-данные не маскируются под рыночные данные.
- В публичном описании остаются только функции, которые реально работают.
- Старые поля баланса и позиций сохраняются только для совместимости локальных профилей; торговые модальные окна и broker-действия из интерфейса убраны.

**Готово, когда:** новый пользователь понимает за минуту, что это исследование и
симуляция, а не биржа и не сервис инвестиционных сигналов.

### 2. Достоверные данные

- Единый слой провайдеров с отметкой времени и источника.
- Исторические данные для воспроизводимого backtest.
- Импорт локального CSV с проверкой формата, дат, цен и лимитов.
- Явные состояния ошибки, устаревших данных и ограничений API.
- В платном режиме нет тихого перехода на mock-данные.

**Готово, когда:** любой результат можно связать с источником и временем получения.

### 3. Strategy Lab

- Paper-only режим с комиссиями и slippage; плечо оставлено отдельным будущим исследовательским сценарием.
- Сравнение стратегий на одном наборе данных.
- Monte Carlo и walk-forward проверки.
- Воспроизводимый отчёт с риском, просадкой и ограничениями.
- Экспорт в CSV и Markdown; PDF добавляется после стабилизации серверной истории.
- Демо-набор и пользовательский CSV визуально разделены в интерфейсе.

**Готово, когда:** пользователь может сохранить исследование и повторить его позже.

### 4. Серверная граница

- `aiGateway` уже разделяет client/server режимы и не передаёт client API keys в server payload.
- Переключение транспорта задаётся явно через `VITE_AI_GATEWAY_MODE` и `VITE_AI_GATEWAY_URL`; по умолчанию остаётся client-режим.
- Серверные аккаунты и сессии.
- Облачное хранение исследований, watchlist и paper-портфелей.
- AI-запросы через gateway с лимитами и журналом расходов.
- Gateway принимает только нормализованный prompt, ограничивает размер запроса и ответа,
  валидирует usage-метаданные и повторно проверяет endpoint/права на сервере.
- Rate limit, аудит и удаление пользовательских данных.

**Готово, когда:** данные пользователя не зависят от одного браузера и AI-ключи не
требуются в клиентском production-коде.

### 5. Обучение и команды

- Импорт курсов из Eclipse Library (контракт подготовки: [education-integration-contract.md](education-integration-contract.md)).
- Практические задания с виртуальным балансом.
- Группы для школ и сообществ.
- Общие исследования и комментарии через Eclipse Chat.

Пока этот этап не запущен: ссылки на Library работают отдельно, а прогресс и аккаунты
между продуктами не синхронизируются.

**Готово, когда:** преподаватель может создать группу, выдать сценарий и получить
сводный отчёт без ручной сборки файлов.

### 6. Монетизация

- `Free`: базовые данные, избранное и ограниченные paper-сценарии.
- `Pro`: история, Strategy Lab, расширенные отчёты и AI-лимиты.
- `Team / School`: группы, курсы, общие исследования и админка.
- `White-label`: отдельный бренд, домен и настройки клиента.

Оплата подключается после появления серверных аккаунтов, лимитов и понятного
пользовательского результата. Реальные сделки в первый коммерческий релиз не входят.

## Критерии релиза

- Нет неподтверждённых функций в интерфейсе и README.
- Нет тихого смешивания live и mock данных.
- Все исследовательские результаты воспроизводимы.
- Пройдены unit, API, E2E и responsive проверки.
- Проверены пустые, offline, timeout, error и loading состояния.
- Отдельно проведены security review и production smoke.

## Срез локального пакета — 2026-11-12

Локально собраны и проверены: paper-only позиционирование, статусы рыночных и новостных
источников, Strategy Lab с CSV, экспортом и отключённым по умолчанию Research API-клиентом, client/server AI boundary с лимитами и
usage-валидацией, локальный тарифный контур, Research Admin и базовые responsive/a11y
правки. Изменения опубликованы в `PavelHopson/CryptoPulse:main` коммитом
`53120e4`; production deploy выполнен на `https://cryptopulse.eclipse-forge.ru`.

Подтверждены статические `bun build` для изменённых TypeScript-файлов, worker build и
worker boundary smoke. Фокусный набор браузерных сервисов (`aiService`, `aiGateway`,
`cryptoService`, `newsService`, `researchApi`, `strategyLab`, CSV import/export и
evidence) прошёл: 100 тестов, 293 проверки; вместе с Worker boundary smoke полный
локальный набор составил 110 тестов и 319 проверок. Worker boundary smoke прошёл: 10 тестов,
26 проверок. GitHub CI run `43280937951` подтвердил typecheck, полный Vitest и Vite build;
production deploy run `43281656138` завершился успешно, smoke по домену вернул HTTP 200.
Playwright E2E и browser-level desktop/mobile QA пока не запускались.

До коммерческого релиза остаются подключение реального identity provider и D1/KV/Rate
Limiting binding, настройка upstream AI gateway, синхронизация Library/Chat, оплата
тарифов и полный desktop/mobile E2E. Frontend production smoke пройден. Reference Worker уже добавлен
в `workers/research-api/`, но не считается production-ready до этих внешних проверок.
У Worker пока нет lock-файла и отдельного runtime CI job: локальная установка
инструментов зависит от доступности npm registry. Его production source теперь
входит в корневой TypeScript-контур, но Worker runtime smoke всё ещё остаётся
отдельным release gate.

После этого среза добавлены доступные состояния для сравнения, входа и Research Admin,
повторная загрузка при ошибке, таймаут server AI transport и запрет незакреплённого
`npm install` в deploy workflow. Server AI по-прежнему намеренно не включён: браузерный
endpoint не является границей безопасности, поэтому сервер должен сам проверять сессию,
Origin/CSRF, allowlist моделей, лимиты, идемпотентность и фактическое usage.
Подробный request/response и операционный контракт зафиксирован в
`docs/ai-gateway-contract.md`. Для Research API локально проходят десять Bun smoke
тестов worker и восемь тестов браузерного клиента; Research API production readiness
по-прежнему не утверждается до внешних binding и runtime smoke-проверок.
Синтетическая таблица сообщества теперь явно помечена как `SYNTHETIC DATA · PAPER ONLY`;
она не выдаётся за реальные аккаунты или историческую доходность.

В текущем локальном проходе дополнительно укреплены desktop/mobile-навигация,
уведомления и theme-menu (keyboard focus, Escape, возврат фокуса, empty state),
добавлены видимые focus rings на ключевых формах, empty state проектных обновлений
и более честное состояние плановых тарифов. E2E-сценарий Strategy Lab синхронизирован
с текущим UI, проверяет сохранение истории после reload, а Playwright теперь имеет
desktop и mobile Chromium-проекты; запуск этих сценариев ждёт доступности зависимостей.
Автоматический VPS deploy теперь запускается после успешного workflow `CI`; ручной
`workflow_dispatch` остаётся отдельным явным путём.
